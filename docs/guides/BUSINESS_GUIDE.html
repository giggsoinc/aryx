What is Aryx Lite?

Aryx is the self-building context layer for AI agents.

In plain language: you connect the data your company already has. Aryx figures out what the things are, when two records are the same real-world thing, and how things link. AI assistants and applications then answer from connected business context, not disconnected files alone.

Aryx Lite is the version you run yourself (laptop, VM, or small server) to prove value quickly—without a multi-year “enterprise ontology program” first.

Retrieval finds information. Aryx connects meaning.

Why it is critical (business POV)

The business problem

  1. Customer 360 is a slogan — same customer, different names in CRM, billing, and support.
  2. Agents sound confident and are wrong — they invent links between systems.
  3. Ops waste time — people manually stitch Salesforce + ERP + tickets + email.
  4. Risk — “the AI said so” needs where the fact came from.
  5. Every AI use case restarts — each bot rebuilds the same context.

Not just another chatbot project

Outcomes that matter

  • Faster, safer AI answers for support, ops, and knowledge work.
  • Less rework building “who is who” into every prompt and bot.
  • Auditability — facts traceable to source records.
  • Reusable context — one workspace graph, many agents and apps.
  • Faster time-to-value than multi-year semantic modeling programs.

git clone https://github.com/giggsoinc/aryx.git
cd aryx
cp .env.example .env
docker compose pull
docker compose up -d

Open http://localhost:3000.

First business success path

  1. Pick one pilot (e.g. support: customers + tickets).
  2. Create a workspace named for the pilot.
  3. Load data first — CSV upload or read-only database.
  4. Smart review — light-edit the proposed plan.
  5. Build — resolve + context graph.
  6. Ask — questions with sources you can open.
  7. Share — decide if agents (Claude / internal bots) may use this workspace.

Using Aryx with Claude, Gemini, or Copilot

Business outcome is the same no matter which chat brand you prefer:

Load data into Aryx once → agents answer from connected context with sources — not from guessing across five systems.

Two roles get confused. Keep them separate:

RoleWhat it doesWho configures
A. Brain inside Aryx Model for smart review, extraction, and Ask (Settings) IT / technical owner
B. Chat app you work in Claude, Gemini app, Microsoft Copilot, Cursor — where you type You + IT

You can use Gemini as Aryx’s brain and still ask in the Aryx web UI. You can use Claude Desktop as the chat app that calls Aryx via MCP. You can use Copilot best through a company app that calls Aryx’s API (or Aryx Ask).

Outcome path (all brands)

1. Build context in Aryx (data first → smart review → build)
2. Pick how people ask:
      • Aryx Ask (web)  — any Settings model
      • Claude + MCP    — Claude tools talk to Aryx
      • Gemini / Copilot — Aryx Ask, or company app/API bridge
3. Ask business questions; open cited sources for proof
4. Fix wrong links with Correct data so the next answer improves

Option 1 — Aryx app (simplest)

  1. IT runs Aryx; sets Settings provider (Ollama, Gemini, Anthropic, OpenAI, Grok…).
  2. Team loads pilot data and builds the graph.
  3. Everyone uses Ask in the web UI.
  4. Answers include citations to entities / source records.

No Claude Desktop or Copilot required. Gemini can simply be the Settings engine.

Good outcome checklist

  • Pilot data in one Aryx workspace
  • Smart review approved by a domain expert
  • Ask (or Claude-via-MCP) returns answer plus sources in Data
  • Wrong merges fixed once in Correct data
  • IT documents supported path: UI only · Claude MCP · API to Copilot/Gemini

How to use (by stakeholder)

Product / LOB owner

  • Name the workspace and pilot aim.
  • One use case per workspace — don’t boil the ocean.
  • Success = correct account + ticket link + visible source.

Operations / support / sales ops

  • Data explorer for entities and sources.
  • Correct data when merges or types are wrong.
  • Ask daily questions with citations — or Claude via MCP if IT enabled it.
  • Preferred chat brand (Claude / Gemini / Copilot) → section above.
  • Stuck jobs → IT: Observe / Jobs (Resume if available).

Data / analytics leadership

  • Provenance and Model quality; Accuracy Lab.
  • Lite = pilot/team scale; Enterprise for larger programs.

Executive sponsor

  • Self-host pilot; keys and access controlled by IT.
  • Lite proves value → Enterprise for scale/governance.
  • Aryx is a context layer under Claude / Gemini / Copilot — not a replacement CRM/ERP.
  • UI Ask works with any Settings model; Claude MCP is the strongest agent-native path; Copilot/Gemini fronts need API bridge or Ask.
  • Competing multi-tenant hosting of Aryx needs commercial terms.

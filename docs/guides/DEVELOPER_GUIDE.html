What is Aryx Lite?

Aryx is a self-building context layer for AI agents.

Aryx Lite is the self-hostable stack: connect databases and files, discover entities and relationships, resolve identity across sources, project a context/knowledge graph with provenance, then serve that context via REST, Ask, and MCP.

Give AI agents connected business context without hand-building and constantly re-maintaining a full semantic model for every domain.
Aryx Lite isAryx Lite is not
Context engine next to your dataA replacement for Postgres or your warehouse
Identity + links + provenance for agents“Just another vector DB”
Discover → resolve → graph → serveOnly an academic ontology studio
Docker-first full stack + Python APIZero-ops multi-tenant SaaS

Stack: Postgres (SoT) · FalkorDB (graph projection) · FastAPI · Next.js · Ollama or cloud LLMs · MCP SSE.

Why it is critical (developer POV)

Problems you actually hit

  1. Same customer is C-991 in CRM, ACME-US in ERP, free text in a ticket.
  2. Every agent re-infers joins inside the prompt.
  3. RAG returns the right paragraph but not the path: customer → contract → product → incident.
  4. No reliable provenance for what justified an answer.
  5. Each new agent reimplements the same glue.

What fails without a context layer

PatternFailure mode
Bigger context windowsNo stable entity IDs across systems
More RAGRelevant chunks ≠ connected facts
Hand-written tools onlyRows without shared relationships
Per-agent memoryPersonal memory ≠ shared business identity

Why Aryx Lite matters to you

  • Ship agent features faster — context is a service.
  • Shared workspace graph — many agents, one identity layer.
  • MCP-native — Claude Desktop / Code and other MCP hosts.
  • HTTP-native — your app calls Ask/API without owning ER.
  • Provenance — debug and audit grounding.
  • Data-first setup — sample → smart plan → build.

How to get started

Requirements: Docker Compose · ~8 GB RAM if using local Ollama · optional cloud LLM key in Settings.

git clone https://github.com/giggsoinc/aryx.git
cd aryx
cp .env.example .env
docker compose pull
docker compose up -d
SurfaceURL
Web UIhttp://localhost:3000
API OpenAPIhttp://localhost:8088/docs
MCP SSEhttp://localhost:8765/sse
Healthcurl -s http://localhost:8088/health

First technical success path

  1. Settings — LLM ready (Ollama or cloud).
  2. New workspace — data-first setup.
  3. Upload examples/quickstart/ customers + tickets CSVs.
  4. Smart review → approve plan → Build.
  5. Data / Model / Ask.
  6. Optional: Claude MCP → :8765/sse.

Compose-first today. Pure pip install of the whole stack is packaging roadmap; the Python package is the engine/API, not Postgres+UI alone.

Mental model: Sources → Discover → Resolve → Project graph → Serve (Ask / API / MCP). Postgres = truth; FalkorDB = rebuildable projection. Not zero-copy federation of every SaaS API.
